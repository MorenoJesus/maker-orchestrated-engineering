# Glossary

**MOE 0.3.0 working draft**

| Term | Meaning in MOE |
| --- | --- |
| Maker | The human accountable for technical coherence and responsible orchestration of a mission. Not a required job title. |
| Mission | A bounded, outcome-oriented unit of authorized work; may map to an existing ticket, story, change, or investigation. |
| Mission Contract | The record of intent, scope, acceptance conditions, authority, constraints, and observation. Not a commercial contract. |
| Delegation Contract | A bounded assignment linked to an authorized mission revision. |
| Autonomy Policy | Effective rules for agent actions and required approvals, enforced by the host environment. |
| Proof Bundle | Candidate-bound evidence references, check results, limitations, and acceptance mapping. Not proof of universal correctness. |
| Decision Record | An attributable, scoped record of a consequential choice, approval, rejection, or exception. |
| Candidate | The exact artifact or change being evaluated, including relevant merge or deployment context. |
| Capability | An activity the lifecycle must support; not necessarily a sequential stage or meeting. |
| Profile | A versioned mapping of MOE to an organizational lifecycle or governance model. |
| Adapter | An implementation boundary to a model, tool, work system, repository, or evidence store. |
| Independent evidence | Evidence inspectable independently of the implementation agent's own assertion. |
| Technical acceptance | An authorized decision that the candidate meets specified acceptance conditions under policy. |
| Outcome observation | Measuring whether the intended effect occurred after delivery. |
| Conformance | An explicitly scoped, evidence-supported assessment against this version's core requirements. |

Use **MOE** with its full expansion at first mention. Avoid confusing it with the unrelated machine-learning term mixture of experts. Use exact local identifiers in integration records; do not rename APIs or commands to match the prose style.
