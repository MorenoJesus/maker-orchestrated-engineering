# Runtime-neutral Skill

Name, purpose, version, owner, intended inputs and appropriate use conditions.

## Procedure
Describe the repeatable method, required source inspection, decisions, output format and self-checks. Preserve exact technical identifiers and distinguish facts, assumptions, proposals and unverified claims.

## Boundaries
State what the skill cannot establish, which decisions require escalation, and which tools require host authorization. Instructions are not an enforcement mechanism.

## Evaluation
Include a positive example, a missing-information example, an adversarial or misleading input, and expected failures. Record changes and compatibility with the consuming runtime separately.

## Communication guidance

Apply the organization's selected communication standard. ECS is this repository's default and an optional reference for adopters. Preserve exact identifiers and raw evidence. Distinguish facts, proposals, and unknowns. Use `not_run` only for known non-execution; otherwise use `unknown` when results are unavailable. See [the ECS profile](../profiles/communication-ecs.md).
