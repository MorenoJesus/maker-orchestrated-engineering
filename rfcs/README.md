# Request for comments process

Use an RFC for core semantics, schemas, conformance, autonomy, licensing, or other consequential framework decisions. Suggested states are proposed, accepted, rejected, superseded, and withdrawn.

An RFC should contain:

- ID
- title
- author or proposer
- status
- date
- affected version
- problem
- proposal
- alternatives
- security implications
- compatibility
- examples
- validation plan
- open questions
- the final decision with authority and rationale

An agent may draft an RFC. Only the authorized project decision-maker can accept it. A merged draft does not automatically settle an open decision unless the decision is explicitly recorded.
