# RFC 0001: foundation decisions

**Status:** proposed | **Date:** 2026-11-06 | **Target:** MOE 0.3.0

## Proposal

Keep MOE vendor-neutral and compatible with existing lifecycles. Treat the maker as an accountability rather than a compulsory job title. Define five logical contracts without requiring five files. Enforce authority outside prompts. Treat proof bundles as scoped evidence, not universal correctness claims. Use self-assessment language rather than certification.

## Decisions recorded

- **License, 2026-11-10.** The repository owner selected the Apache License, Version 2.0 for all repository content. The text is in [LICENSE](../LICENSE). No rationale was recorded with the decision. This settles the license part of item 1 below.

## Decisions awaiting the repository owner

1. Decide whether to adopt contribution terms beyond section 5 of the selected license.
2. Approve or amend the proposed project governance and private security-reporting route.
3. Choose the scope, baseline, guardrails, and participants for an initial pilot.
4. Decide whether to tag 0.3.0 after reviewing this foundation.

## Alternatives

A tool-specific framework would simplify one integration but reduce portability. A strict replacement lifecycle would be easier to diagram but impose unnecessary adoption cost. A heavyweight mandatory document set would improve consistency at the cost of proportionality. The proposal rejects these defaults.

## Validation

Run schema and semantic checks, challenge the controls with negative cases, and review usability across different lifecycle profiles. A successful validation run does not close the owner decisions above or establish real-world effectiveness.
